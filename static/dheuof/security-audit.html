01طبيعة المشروع ونطاق الفحص

Scope · what this codebase is, what it isn't
SCOPE

هذا المشروع نظام تصميم (Design System) — ليس تطبيقاً عاملاً

Static mockups · no backend · no live data flow

المشروع مكوّن من ملفات .html، .css، و .jsx ستاتيكية تعرض شكل واجهات منتج ضيوف. لا يوجد خادم، قاعدة بيانات، مصادقة فعلية، أو معالجة حقيقية للدفع. ميزات «الدفع المخصص» و«العقد المخصص» و«SMS» التي أضفناها هي عرض بصري فقط — لا يوجد رابط دفع حقيقي ولا إرسال SMS فعلي.

لذلك ينقسم التقرير إلى: (أ) فحص الكود الستاتيكي الموجود فعلاً، و(ب) متطلبات أمنية يجب الالتزام بها قبل تشغيل الميزات في الإنتاج.

Static analysis · every line of JS/HTML/CSS in the project
PASS

لا توجد أسرار أو مفاتيح مكشوفة

No exposed secrets, API keys, tokens, passwords, bearer tokens

تم البحث بـ regex شامل عن api[_-]?key | secret | token | password | bearer | authorization | private[_-]?key في كل الملفات. لم يُرصد أي مطابقة فعلية — فقط ذكر كلمة tokens في animations.js كمتغيّر محلي لتقسيم نص (لا علاقة له بأسرار).

STATIC-01
PASS

لا توجد دوال خطرة أو تنفيذ ديناميكي

No eval / document.write / dangerouslySetInnerHTML / new Function

لا يوجد أي استخدام لـ eval()، new Function()، document.write، أو dangerouslySetInnerHTML في React. استخدامات innerHTML الموجودة في slides/deck-stage.js (3 مواضع) كلها قوالب نصّية ثابتة بدون أي مدخلات مستخدم — آمنة بطبيعتها.

STATIC-02
PASS

لا توجد طلبات شبكة فعلية

Zero outbound network calls · zero data exfiltration vectors

لا يوجد أي fetch()، XMLHttpRequest، WebSocket، أو navigator.sendBeacon. الموارد الخارجية الوحيدة هي: Google Fonts (للخطوط فقط، عبر @import في colors_and_type.css)، وunpkg.com لـ React/ReactDOM/Babel كسكربتات مكتبة معروفة.

STATIC-03
PASS

سكربتات CDN محصّنة بتجزئة سلامة (SRI)

All CDN scripts pinned with integrity hashes + crossorigin="anonymous"

كل ملفات HTML تستخدم React 18.3.1 و Babel 7.29.0 من unpkg.com مع integrity="sha384-..." و crossorigin="anonymous". هذا يمنع هجوم استبدال السكربت (Supply-chain attack) — لو تغيّرت بايتة واحدة من الملف على CDN، المتصفح سيرفض تنفيذه.

STATIC-04
LOW

تثبيت إصدار خطوط Google Fonts

Google Fonts @import — depends on Google's CDN integrity

الخطوط تُحمَّل من fonts.googleapis.com بدون SRI (لا يدعمه CSS @import). البديل: نشر ملفات .woff2 محلياً في fonts/ — الـ README.txt يشير إلى وجود هذا الخيار. توصية: استخدم الخطوط المحلية في الإنتاج لتقليل اعتمادية الطرف الثالث ولامتثال الخصوصية (Google Fonts يسجّل IP الزائر).

STATIC-05
LOW

عدم وجود رؤوس أمان (Security Headers)

No CSP, X-Frame-Options, Referrer-Policy meta tags in HTML

ملفات HTML لا تحتوي على <meta http-equiv="Content-Security-Policy"> أو رؤوس مماثلة. هذا غير حرج للماكيت الستاتيكي، لكن عند النشر يجب ضبط على مستوى الخادم: CSP صارمة، X-Frame-Options: DENY، Referrer-Policy: strict-origin-when-cross-origin، Permissions-Policy لتعطيل الكاميرا/الميكروفون/الموقع.

STATIC-06
LOW

سكربتات React/Babel التطويرية

Using react.development.js + @babel/standalone in-browser

كل الواجهات تستخدم react.development.js و Babel بالمتصفح. هذا مناسب للماكيت، لكنه: (١) أبطأ، (٢) يكشف رسائل debug، (٣) يُحمّل ~٣ ميجابايت إضافية. في الإنتاج: استخدم react.production.min.js وحوّل JSX إلى JS مسبقاً (Vite/Next/Webpack)، ولا تشحن Babel للمتصفح.

04متطلبات تأمين «نظام الدفع المخصص»

Production hardening · before the payment builder accepts real money

على الواجهة (Front-end)

تفويض الحقول الحسّاسة لـ PCI iframe. لا تُلامس رقم البطاقة، CVV، أو تاريخ الانتهاء كود ضيوف إطلاقاً — استخدم iframe مزوّد الدفع المعتمد (HyperPay / PayTabs / Moyasar / Checkout.com) داخل صفحة الدفع المرسلة عبر SMS.
Card data must NEVER touch Dheuof origin — PCI-DSS scope minimization
تشفير HTTPS + HSTS. رابط pay.dheuof.sa يجب أن يُقدَّم حصراً على TLS 1.3 مع رأس Strict-Transport-Security: max-age=63072000; includeSubDomains; preload.
TLS 1.3 enforced · HSTS preloaded
CSP صارمة على صفحة الدفع. default-src 'self'; script-src 'self' <PSP-domain>; frame-src <PSP-domain>; form-action 'self' <PSP-domain>; لا تسمح بـ unsafe-inline أو unsafe-eval.
Strict CSP · no inline JS · whitelist PSP frames only

على الخادم (Back-end)

روابط الدفع موقّعة وقابلة للإلغاء. كل رابط = توكن JWT أو OPAQUE موقّع HMAC-SHA256، صلاحيته ≤ ٧٢ ساعة، استخدام واحد فقط (single-use)، يبطل تلقائياً عند الدفع.
HMAC-signed · single-use · TTL ≤ 72h · revocable
التحقق من قيمة الدفعة على الخادم — لا الواجهة. أي تعديل على المبلغ من DevTools يجب أن يُرفض. المبلغ مصدره دائماً ID الحجز + جدول الدفعات في قاعدة البيانات.
Server-side amount enforcement · never trust client total
Webhook موقّع من مزوّد الدفع. إشعار نجاح الدفع يُتحقّق منه عبر توقيع المزوّد (مثل X-Signature في PayTabs) — لا تعتمد على إعادة توجيه المتصفح فقط.
Verify PSP webhook signature · don't trust redirect-only confirmation
التشفير في الراحة (Encryption at rest). بيانات الحجز، أرقام الهوية، آخر ٤ خانات من البطاقة (PAN truncation) — كلها مشفّرة في DB بـ AES-256-GCM ومفاتيح في KMS/HSM.
DB encryption · KMS-managed keys · PAN truncated to last 4
Rate-limit + كشف الاحتيال. أكثر من ٣ محاولات دفع فاشلة لنفس IP / نفس رقم حجز خلال ١٠ دقائق → CAPTCHA إجباري + تنبيه أمني.
Rate-limit failures · velocity checks · CAPTCHA after threshold
سجل تدقيق غير قابل للتعديل (Audit log). كل تعديل على جدول الدفعات (إنشاء/حذف/تعديل مبلغ) يُسجَّل بـ user_id, timestamp, IP, before/after — append-only.
Immutable audit log · who-changed-what-when

05متطلبات تأمين «العقد المخصص»

Digital contract integrity · e-signature legal validity

سلامة وثيقة العقد

تجميد المحتوى عند الإرسال (Content freeze). لحظة الضغط على «إرسال للتوقيع» — يُولَّد PDF نهائي مع hash (SHA-256)، ويُخزَّن. أي تعديل لاحق على البنود يفرض إعادة إرسال + توقيع جديد.
SHA-256 of frozen PDF · any clause change invalidates signature
تطهير حقول الدمج (Template injection). قيم مثل {{اسم_النزيل}} تُعالَج بمكتبة قوالب آمنة (Mustache/Handlebars بدون helpers)، ولا تُمرَّر إلى محرّك يدعم تعليمات. التطهير ضد HTML/PDF injection إجباري.
Sandboxed template engine · escape all interpolated values
توقيع رقمي معتمد. خيار «نفاذ» يُوصى به للعقود ذات الأثر النظامي (طبقاً لنظام التعاملات الإلكترونية السعودي). خيارات OTP/البصمة مناسبة للعقود الفندقية اليومية، لكن وثّق نوع التوقيع داخل العقد نفسه.
Nafath for legally-binding · OTP/biometric for routine stays · embed sig-type in doc
Timestamp موثوق (RFC 3161). وقت التوقيع يُختم من خادم TSA معتمد، لا من ساعة المستخدم.
RFC 3161 trusted timestamp · not client clock
أرشفة طويلة الأمد. العقود الموقَّعة + سجل الأحداث (إرسال، فتح، توقيع، نسخة مخزَّنة) — تُحفظ ٧ سنوات على الأقل (نظام الفنادق + ZATCA).
7-year retention · ZATCA + tourism regulation compliance

06متطلبات تأمين «ربط SMS»

SMS dispatch · OTP delivery · phone-number trust

قناة الإرسال

مزوّد SMS معتمد محلياً. استخدم مزوّداً مرخّصاً من هيئة الاتصالات (مثل Unifonic أو Mobily Business)، مع اسم مرسِل مسجَّل (Sender ID) موافق عليه لكل نطاق دولي.
CITC-licensed SMS provider · approved sender ID
تحقّق ملكية الجوال قبل أي إرسال حسّاس. أول مرة تُرسل لرقم جديد → OTP تحقّق + موافقة صريحة على استلام رسائل دفع/عقد. لا «تخمين رقم» من بيانات الحجز فقط.
Verify phone ownership before sensitive sends · explicit consent
روابط قصيرة على نطاق مملوك. استخدم pay.dheuof.sa و sign.dheuof.sa مباشرة — لا تستخدم bit.ly أو tinyurl. الروابط القصيرة العامة تسمح بإعادة توجيه السكربت لرابط آخر بعد الإرسال.
Own-domain short links only · no third-party shorteners
التوكن في الرابط — عشوائي وغير متسلسل. 8KQ2-AHM الموجود في الماكيت توضيحي. الفعلي يجب أن يكون ١٢٨ بت من crypto.randomBytes base32-معدّل — غير قابل للتخمين أو الزيادة العددية.
128-bit cryptographic random · not enumerable
عدم تضمين بيانات حسّاسة في نص SMS. الرسالة قد تُرى على شاشة القفل. لا تضع رقم الهوية، آخر أرقام البطاقة، أو المبلغ كامل المفصّل. اكتفِ بـ «دفعة مستحقة» + الرابط + اسم العلامة.
Never put PII/full amounts in SMS body · lock-screen leak vector
Throttling لكل رقم. أقصى ٣ رسائل/ساعة، ٥/يوم، لنفس الجوال — يمنع إساءة الاستخدام من حساب موظف مخترق.
Per-MSISDN throttle · prevent abuse from compromised staff account

OTP (إذا كان طريقة التوقيع)

٦ خانات، صالح ٥ دقائق، استخدام واحد. ٣ محاولات فاشلة → حظر ١٥ دقيقة. لا OTP بنفس القيمة لنفس الرقم خلال ٢٤ ساعة.
6 digits · 5-min TTL · single-use · 3-strike lockout · no replay window

07قالب رؤوس الأمان للنشر

Drop-in security headers for the production reverse-proxy / CDN
# nginx / Caddy / Vercel — security headers for dheuof.sa, pay.dheuof.sa, sign.dheuof.sa add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always; add_header X-Frame-Options "DENY" always; add_header X-Content-Type-Options "nosniff" always; add_header Referrer-Policy "strict-origin-when-cross-origin" always; add_header Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=(self)" always; add_header Cross-Origin-Opener-Policy "same-origin" always; add_header Cross-Origin-Resource-Policy "same-site" always; # CSP — tighten per page. Below is for pay.dheuof.sa with HyperPay iframe add_header Content-Security-Policy "default-src 'self'; \ script-src 'self' https://test.oppwa.com https://oppwa.com; \ style-src 'self' 'unsafe-hashes'; \ frame-src https://test.oppwa.com https://oppwa.com; \ form-action 'self' https://oppwa.com; \ connect-src 'self'; img-src 'self' data:; \ font-src 'self'; object-src 'none'; base-uri 'self'; \ frame-ancestors 'none'; upgrade-insecure-requests;" always;

08الامتثال التنظيمي السعودي

PDPL · ZATCA · CITC · tourism law
PDPL

نظام حماية البيانات الشخصية

Personal Data Protection Law · Saudi Arabia

الحصول على موافقة صريحة قبل إرسال SMS تسويقي. الحقّ في الوصول/التصحيح/الحذف. تعيين Data Protection Officer للمنشأة. إشعار بالاختراق خلال ٧٢ ساعة لـ SDAIA.

ZATCA

الفوترة الإلكترونية

E-invoicing Phase 2 · Fatoorah

كل دفعة من جدول «الدفع المخصص» تُولّد فاتورة ZATCA-compliant (XML + QR + توقيع رقمي + cryptographic stamp). تكامل مع بوابة هيئة الزكاة والضريبة والجمارك إجباري.

CITC

هيئة الاتصالات

Sender ID registration · message templates

أسماء المرسلين («Dheuof») تُسجَّل وتُعتمد. قوالب الرسائل المعاملاتية (دفع/توقيع) تُقدَّم للموافقة. المراسلات التسويقية تتطلب opt-in موثّق.

TOUR

نظام الفنادق

Hotel registration · Shumūs reporting

بيانات النزلاء تُرفع لمنصة «شموس» خلال ٢٤ ساعة من الوصول. الحفاظ على السجلات ٧ سنوات. عقود الإقامة تُرتبط برقم الحجز في شموس.
